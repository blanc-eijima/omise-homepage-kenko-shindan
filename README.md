# おみせのホームページ健康診断

町の小さなお店の人が、自分のホームページのURLを入力すると、外部から確認できる情報だけを調査し、次の3つを専門用語なしで返します。

- 現在どのような問題があるか
- 放置するとどのような問題が起きるか
- 誰にどのような修正を依頼すればよいか

業者に任せきりで、壊れても誰に何をどう頼めばいいか分からない。その壁を取り払うためのツールです。

「Built with Claude: Japan 2026」の期間中（2026-11-02〜）に新しく作っています。

## 現在できること

URLを渡すと、次の項目を調査してJSONで出力します。

- SSL証明書の期限と、httpからhttpsへの転送
- ドメインの期限（.jp を含む）
- トップページが開くか、エラーメッセージが表示されていないか
- WordPressとPHPのバージョン（バージョン情報が公開されている場合のみ）
- 検索エンジンに表示されない設定（noindex・robots.txt）と title の有無
- スマホ向けの設定（viewport）
- メールの設定（MX・SPF・DMARC）
- お問い合わせフォームの送信先（HTMLを読むだけで、送信はしません）
- サイトとGoogleマップの電話番号の食い違い（`.env` に `SHINDAN_PLACES_API_KEY` があるときだけ）

結果には、管理・制作会社を特定するための参考情報（ネームサーバーとメールサーバーのドメイン、サイト内に記載された制作会社情報）も付きます。判定には使わず、Claudeにも渡しません。

`--explain` を付けると、Claude が調査結果を読み、緊急度の高い順に整理した説明と依頼先ごとの依頼文を書きます。出力は調査結果と突合し、調査結果に含まれない数値・ドメイン名・項目を書いていたら差し戻します。

```
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python -m shindan.cli https://example.com
.venv\Scripts\python -m shindan.cli --explain https://example.com
```

画面で使うときは `.venv\Scripts\python -m shindan.web` を実行し、`http://127.0.0.1:8765/` を開きます。

公開版は https://shindan.blanc.to/ です。

`--explain` と画面の説明文には `.env` の `ANTHROPIC_API_KEY` を使います。

## 毎月の自動診断（保守する側のツール）

Managed Agents のスケジュール実行で毎月1日に診断し、前回の診断から悪化した項目だけを報告します。比較処理は `shindan/watch_diff.py` のプログラムで行い、エージェントは診断の実行と結果の通知のみを担当します。サイトの一覧と前回の結果はメモリストアに置き、リポジトリには入れません。サンドボックスにキーは渡さないので、Googleマップの照合は行いません。

```
.venv\Scripts\python -m shindan.watch setup https://www.example.jp/
.venv\Scripts\python -m shindan.watch run
.venv\Scripts\python -m shindan.watch schedule
.venv\Scripts\python -m shindan.watch report
```

2サイトの診断にかかる費用は約$0.04（実測）、上限は$0.50です。仕様は `SPEC.md` にあります。

## デモ用の架空サイト

`demo-site/` は動画と確認のために作った架空のお店のサイトです。実在せず、ページにもそう書いてあります。意図的に古いバージョン情報を表示し、画面上に表示されるPHPのエラー・検索エンジンに表示されない設定・暗号化されていない通信先へ送信するフォームを入れています。フォームは押してもどこにも送信されません。架空のお店はGoogleマップに載らないので、このサイトの照合だけは決めておいた架空の登録と比べ、画面に「デモ用の架空データ」と出します。

`demo-site-fixed/` は同じお店を直した後の版で、動画で再診断するために置いています。問題が解消されたことを確認できるようにするためのものなので、バージョン情報は最新のものに更新します。検索エンジンに表示されない設定も外してあるので、検索結果に表示されることがありますが、ページには架空のお店と書いてあります。

## 分かっている限界

- `xxx.netlify.app` のような共有ドメインでは、ドメインの期限とメールの設定はお店ではなく共有ドメイン自身のものを見ます
- 管理画面内の情報は確認できません。WordPressのプラグインが古くても「指摘なし」になることがあります。各プラグインの公開ファイルを確認すれば、バージョンを特定できる場合がありますが、脆弱性調査との境界が曖昧になるため行っていません

## 調べ方の約束

- 外部から誰でも確認できる情報だけを読み取ります。フォームの送信、ログイン操作や認証の試行、脆弱性の調査はしません
- 非公開のIPアドレスや内部ネットワークにはアクセスしません
- 読み解きの文章は、調査結果に含まれる事実だけから作ります
- 調査結果は説明文を作るためにAnthropic社のClaudeへ送ります。サイト側では保存しません
- 公開版は全体で1日30回、同じ接続元から1時間に5回までです

## 公開の手順

Fly.io（東京）で動かします。キーは `fly secrets` に入れ、`.env` は `.dockerignore` でイメージから外しています。

```
fly deploy --remote-only --ha=false
```
